- The interactive codex contributor delivers its task prompt as an explicit bracketed paste (`tmux load-buffer` + `paste-buffer -p`) instead of a raw `send-keys -l` keystroke burst, and no longer treats an empty-looking input widget as a submitted prompt ([#9078](https://github.com/hivecommons/hive/issues/9078)). With codex-cli 0.157.1 a task-sized (~6.8 KB) burst was held invisibly — the widget kept its idle hint, the Enters started no turn, and a truncated `[Pasted Content 4096 chars]` surfaced seconds later — so four consecutive assignments logged `Task prompt sent to CLI` and failed eight minutes later with `pane went idle before codex produced any task output`. Delivery is now acknowledged in three states (`sent`, `started`, `unknown`): after the Enter the relay waits up to 15 s for codex's working row or a fresh tool/verdict row, logs `Task prompt delivery: <state>`, and an `unknown` delivery whose pane is still unchanged (or still holds the collapsed prompt) at the next progress tick is failed there as an `environment` failure — one interval after dispatch, never re-pasted and never re-submitted, so a widget silently holding the first delivery cannot produce a doubled or truncated turn. The codex pane classifier now reads its activity window over non-blank rows, so a turn in flight at the top of a tall (200×50) pane is recognised as working rather than idle. `bin/test_backend_smoke.sh` gains scenario S4, a real-tmux delivery check into a raw-mode, bracketed-paste codex-shaped stub that must receive a 6,868-character prompt and a short control byte-for-byte as exactly one turn each. Other backends keep the literal keystroke transport.
